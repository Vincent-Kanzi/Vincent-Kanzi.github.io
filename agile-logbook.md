## 4. Technical Challenges and Problem-Solving

The redevelopment of an existing application introduces
technical considerations that must be addressed carefully.

### Challenge 1: Maintaining Existing Functionality

Changes to an existing application can affect other components
that depend on the same models, database relationships or workflows.

**Improvement approach:** Review the existing implementation
before making changes and test related functionality afterwards.

### Challenge 2: Request Management

Different service request types have their own requirements,
but should remain accessible through a consistent Requests
experience.

**Improvement approach:** Maintain a unified request management
approach while respecting the individual requirements of VPN,
Printing Credits and SMS Credits.

### Challenge 3: Notification Handling

Request status changes need to be communicated to the relevant
staff members.

**Improvement approach:** Review notification triggers, database
notification delivery, email delivery and the relationship between
request updates and notification records.

### Challenge 4: User Interface Consistency

Administrative and staff-facing pages should provide a consistent
experience.

**Improvement approach:** Use consistent styling, navigation,
spacing, typography and component layouts.

## 6. Sprint Retrospective

### What Went Well?

The redevelopment provides an opportunity to work with an existing
institutional application and understand how its components
interact.

Working with Laravel and Filament also provides practical exposure
to structured application development and administrative
functionality.

The use of version control supports organised development and
allows changes to be reviewed.

### Challenges Faced

Maintaining existing functionality while introducing improvements
requires careful consideration.

Understanding the relationships between different request types,
administrative processes and notifications can also require
additional investigation.

Testing changes is important because an improvement in one area
should not introduce unexpected problems elsewhere.

### What Could Be Improved?

- Improve documentation of system requirements.
- Maintain clearer task assignments and progress records.
- Test affected functionality after each significant change.
- Improve communication around shared development components.
- Record technical decisions and outstanding issues.
- Review the Product Backlog regularly.

## 7. Improvement

The retrospective should be used to identify practical actions
for future development iterations.

The team should use lessons learned from previous work to improve
planning, communication, implementation and testing.

## 8. Reflection

Working on the OPA redevelopment connects software development
concepts with the practical requirements of an institutional
application.

The project reinforces the importance of understanding existing
systems before modifying them, maintaining reliable request
workflows and considering the needs of different user roles.

It also demonstrates that software development is an iterative
process. Requirements can evolve, technical challenges can emerge
and improvements need to be evaluated through testing and feedback.

Applying Agile principles provides a structured approach to
organising this work while supporting collaboration and continuous
improvement.
